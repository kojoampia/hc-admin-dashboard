# There are no E2E tests

`src/test/javascript/cypress/` used to live here: 32 generated specs covering every entity, plus a
`tsconfig.json`. **None of them had ever run.** Cypress was not a dependency, there was no `e2e`
script, and nothing in CI invoked them — they were generated by JHipster and left in place.

They were deleted rather than kept, because a directory full of specs reads as coverage. It was not
harmless: two of the defects the 2026-08 audit found in this repo were exactly what an E2E pass
catches and 1069 unit tests do not — the dashboard opening a WebSocket to a `/websocket` endpoint no
backend implemented, and a live Photo screen calling an `/api/photos` the service had never
generated. Both are integration seams. Both survived a green suite.

If E2E is wanted, it has to be installed and wired for real:

1. `npm i -D cypress` (or Playwright — nothing here depends on the choice)
2. an `e2e` script in `package.json`
3. a CI job that runs it against a started stack, not a mocked one — a stack, because the point is
   to exercise the seam between this app and the gateway
4. the specs themselves; the deleted ones are in git history if they are a useful starting point

Until then, this file is the honest answer to "where are the E2E tests".
